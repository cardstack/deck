The Deckbook

Deck is a protocol for versioning, publishing, and serving ES modules and JSON from plain state — a directory tree, an import map, seals, and immutable version pointers. This book teaches the running reference implementation: CLI, store, server, history, and the workflows they unlock.

Reference impl built Tier‑1 store always on Tier‑2 history optional No framework required

1. The promise

No npm. No GitHub. No deploy. No PR — for the loop that matters while you are building. Edit a file, see it live, keep every settled state, ship a name when you mean it, share a zip anyone can open, pull any ESM library in-house, fork without consequences.

PromiseMechanism (implemented)
Instant feedbackVersion-less URL → working tree, Cache-Control: no-store
Never lose workAuto-publish <base>-dev.N + optional per-save seals
Revert anytimedeck unpack a pack, or deck restore <changeId> (tier 2)
Ship any versiondeck release --from dev — pointer, zero bytes copied
Share a milestonedeck pack → .pack.zip (standard zip)
Use any librarydeck vendor hermetic CDN graph → your store
Fork freelydeck fork into your publisher scope
Stability on demanddeck lock turns ranges into exact pins
Whole web platformPlain ESM + import maps; no bundler required

Borrowed lightly from trading-card games — because a Deck package is an arrangement, not a sealed npm box.

3. The layout is the address

What ls shows and what the URL says are the same shape. A depot carries its machinery inside itself — .deck/store/ for sealed versions, .jj/ for seals — both invisible to the tree hash, so copying the directory takes live files, published versions, and history with it. 

<root>/site/acme/palette/palette.js     on disk
       /site/acme/palette/palette.js    live — every save, no-store
       /site/acme/palette@1.1.0/palette.js
                                        sealed copy, immutable forever
       /site/_history/<changeId>/acme/palette/palette.js
                                        any state it was ever in (tier 2)
Publisher segment = fork boundary. acme/palette and you/palette are different decks with different version lines in the same depot. Undiverged forks cost no extra pack bytes — the store is content-addressed.

4. Three levels of volatility

All just import-map values / URL forms. Opting into churn is always explicit.

You wantYou writeYou get
Every save, instantly"live" / version-less URLWorking tree, no-store
Freshest auto-seal"dev" or @devShort-TTL redirect to newest -dev.N
Something dependable"^1.0.0" / exactStable resolution; ranges ignore prereleases

latest is a dist-tag on a stable release. latest is not live — live is the bytes on disk with no version segment.

5. The live loop

The core vibe-coding workflow, as implemented:

deck hello ./work          # scaffold + serve (or: deck serve --root ./work)
# edit anything under a deck directory
# → debounce (~500ms quiet)
# → treeHash unchanged? stop
# → packFromDir → publish <base>-dev.N, tag:dev
# → [tier 2] history backend seals the save too

deck release --depot ./work/site --publisher acme --name palette \
  --version 1.1.0 --from dev --tag latest

HMR-lite

/_live/events (SSE) + drop-in /_live/hmr.js reloads pages that depend on changed live decks.

Import-map injection

HTML responses get a real inline import map (browsers ignore external map scripts). Sealed pack bytes stay untouched.

6. Store & packs

At rest, each package lives under the depot store:

<depot>/.deck/store/<publisher>/<name>/
  meta.json                          # versions + dist-tags (pointers)
  packs/<treeHash>.pack.zip          # bytes once per content hash
  • Publish verifies a pack, writes bytes only if the treeHash is new, then adds a version pointer.
  • Release names an existing sealed state — never copies bytes.
  • Prune drops old -dev.N records; deletes pack files only when nothing still points at them.
  • Pack laws: treeHash survives pack→unpack; pack∘unpack is byte-identical for canonical packs; stock unzip works.

7. History tiers (be honest)

TierWhat you getStatus
1 — store only Every settled save → immutable -dev.N pack. Restore by unpacking. No seals between publishes. Always on
2 — jj / historyd Every save sealed; /<depot>/_history/<changeId>/…; deck history / deck restore; packlist can name sealChangeId. Implemented when --history auto|jj|historyd attaches
Capability is reported, not pretended. GET /_packages includes a history block (tier, jj, historyd). Missing jj or a dead daemon degrades to tier 1 with a printed reason — the live/auto-publish loop keeps working. 
deck serve --root ./work --history auto
deck history ./work/site
deck restore ./work/site <changeId>   # leaves current state sealed first

8. Safe vendor — your own unpkg

Pull a CDN module graph once, rewrite references to stay inside the pack, seal it. Runtime imports hit your Deck server only. Hermetic by default; --allow-external / --allow-host are explicit opt-outs. Identity travels as vendoredFrom. 

deck vendor https://esm.sh/simplex-noise@4.0.1 \
  --name simplex-noise --version 4.0.1 \
  --depot ./work/site --publisher acme --tag latest
<script type="importmap">
{ "imports": { "simplex-noise": "/site/acme/simplex-noise@4.0.1" } }
</script>

9. Fork, lock, offers, rebase

Contribution is a version you can run, not a diff waiting for merge theater.

Fork

deck fork --depot ./work/site \
  --from acme/palette --as you/palette --use-in you/app

Copies into your publisher scope; optional --use-in repoints a consumer at the fork live. Records base (package, version, treeHash) so the fork is an offer.

Lock

deck lock --depot ./work/site --publisher you --name app
deck lock --depot ./work/site --publisher you --name app --check

Resolves declared ranges to exact pins in the import map — users never inherit someone else's working tree.

Try by URL

/site/you/app/index.html?with=acme/palette=you/palette
/site/you/app/index.html?with=acme/palette@1.1.0

Server rewrites resolution for that request only. No checkout, no build, not cached as sealed content.

Offers & rebase

deck offers --depot ./work/site
deck rebase --depot ./work/site          # or: deck serve --rebase
GET /site/_offers
  • Clean merges write into the proposal tree (auto-publish + seal).
  • Conflicts are reported and left untouched — machines never damage contributor work.
  • JSON merges as data (key-level), not as lines — so adding adjacent keys is not a fake conflict.
  • Accepting a proposal is a pointer move to a treeHash already held. Zero bytes copied.

12. Use cases the protocol earns

From docs/deck-use-cases.md — shapes of work that need this, not merely benefit.

Swarm-built internal tool

Eight agents, eight decks under one app import map. Composition is continuous — no integration branch. Quarantine a bad agent by pinning one dependency from live to ^1.2.0. Dial volatility per component.

Codelists & reference data

JSON merges as data (implemented). Amendments publish as dev; ranges never see them. Forks keep absorbing upstream via rebase daemon — your three private keys stay, and you stay current.

Adapters → patterns → instances

One address space for stable adapters (^2.0.0), vibe patterns (live), and instance JSON. Promote bespoke→generic with deck fork, not a rewrite in another product.

Skills & agent capabilities

Versioned, forkable, try-by-URL evaluable. Hundreds of tiny edits stay sealed; review means running the harness with ?with=, not reading the prompt.
